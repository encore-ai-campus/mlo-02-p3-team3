# 공연별 예매 오픈과 좌석 초기화

Compose로 실행하는 웹은 한국 시간 매시 정각부터 공연 목록 순서대로 5분 간격으로
새 예매를 시작한다. 각 공연의 좌석은 그 공연의 오픈 시각에서 정확히 1시간 뒤
초기 상태가 되고, 즉시 다음 예매 주기가 시작된다. 매진되더라도 초기화 시각은
앞당겨지지 않는다.

| 공연 | 매시간 오픈·초기화 시각 (한국 시간) |
|---|---|
| 겨울밤의 재즈 | 00분 |
| 첫눈의 선율 | 05분 |
| 11월의 마지막 밤 | 10분 |
| 겨울의 왈츠 | 15분 |
| 마음을 녹이는 밤 | 20분 |
| 온기 (`blue-hour`) | 25분 |
| 겨울의 문턱 (`open-air`) | 30분 |
| 입동의 소리 (`spring-concert`) | 35분 |
| 온기 (`city-night`) | 40분 |
| 겨울의 문턱 (`starlight`) | 45분 |
| 입동의 소리 (`summer-rhythm`) | 50분 |

순서는 `web.services.SHOWS`의 등록 순서를 따른다. 지정석은 100석 전체를 다시
선택할 수 있고, 자유석은 기존 초기 수량인 28명으로 복구한다. 진행 중인 이전
주기의 대기·보안 확인·좌석 선택은 만료된다. 완료된 예매 내역과 구매 원장은
보존하며, 이전 완료 요청을 재시도하면 기존 예매를 반환한다. 계정당 4매 한도는
각 주기에 새로 계산한다. 계정 인증과 나머지 방어 정책은 유지한다.

## 배포 설정

`compose.yml`은 웹에 다음 기본값을 전달한다. 과거 정각을 기준점으로 사용하므로
서버를 재시작해도 매시간의 오픈·초기화 시각이 달라지지 않는다.

```text
BOOKING_OPENS_AT=1970-01-01T00:00:00+09:00
```

첫 오픈 전 대기를 두려면 `.env`에서 시간대가 포함된 ISO 시각을 지정한다.
예를 들어 아래 값이면 첫 공연은 해당 날짜 14:00, 두 번째 공연은 14:05에
처음 열리고, 그 뒤 매시간 반복한다.

```text
BOOKING_OPENS_AT=2026-12-01T14:00:00+09:00
```

새 설정을 적용하려면 기존 배포 절차로 웹 컨테이너를 다시 생성한다.
코드만 동기화하고 실행 중인 프로세스를 유지하면 설정은 반영되지 않는다.
Compose 없이 직접 Python으로 실행할 때는 같은 환경변수를 별도로 설정한다.
Python 설정에서 값이 비어 있으면 기존 상시 예매 동작을 사용한다.

기능을 처음 켜면 기존 주기 정보가 없는 좌석 재고는 새 주기의 초기 상태로
바뀌고, 진행 중인 기존 예매는 만료된다. 완료 내역은 삭제하지 않는다.

## 동기화와 검증

좌석 화면은 기존 heartbeat를 2초 간격으로 호출해 다른 사용자가 확정한 좌석을
비활성화하고, 선택 중이던 좌석이 판매되면 선택에서 제외하고 안내한다.
자유석 잔여 수량도 갱신한다. 최종 구매 판단은 MongoDB 트랜잭션 안에서 하므로
화면 갱신 전에 구매가 경합해도 같은 좌석을 두 번 판매하지 않는다.

상세 화면은 `/api/shows/<show_id>/availability/`에서 서버 시각과 오픈·초기화
시각을 받아 카운트다운을 보정한다. 다른 브라우저의 시계에 구매 권한을 맡기지 않는다.

초기화는 별도 타이머 작업으로 데이터를 삭제하는 방식이 아니다. 서버 시각으로
현재 주기를 계산하고, 재고를 읽거나 예매할 때 MongoDB 트랜잭션 안에서 재고를
전환한다. 접속자가 없는 동안 여러 시간이 지나도 다음 요청은 현재 주기의 빈
재고를 보며, 주기의 종료 시각을 다음 요청 시점부터 다시 계산하지 않는다.
한 트랜잭션에서는 같은 기준 시각을 사용해 시간 경계에서 서로 다른 주기의
구매·재고가 섞이지 않게 한다.

테스트:

```powershell
$env:TEST_MONGO_URI = 'mongodb://127.0.0.1:27029/test?directConnection=true'
python manage.py test web.test_booking_schedule -v 2
node tests/booking-inventory.cjs
python manage.py test web -v 1
```

MongoDB는 `compose.state-test.yml`의 격리 복제 세트를 사용한다.
테스트 주소에 운영·QA DB를 지정하지 않는다.
